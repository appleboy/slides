AI 工具爆發時代的企業身分認證治理實戰

公司內的 AI Agent、MCP Server、CLI 與自動化腳本兩年內成長數十倍，每一個都要登入、都要授權。這場分享我們如何把「機器身分」當成一等公民治理：用統一認證閘道取代各自接 LDAP，用 Device Flow 與 PKCE 杜絕寫死金鑰，讓每顆 Token 都查得到、管得住、關得掉。

AI 驅動的軟體開發資安新思維

被 AI 自動化放大的三個風險

MCP、Skill 服務、Bot、Web 工具、CLI 各自實作認證。工具一多，個別小問題就升級成系統性的資安風險。

認證各自造輪子

每個服務自己接 LDAP，bind 帳密散落各處，安全標準不一。LDAP 一異動，所有服務得一起改，也沒有統一的登入紀錄。

金鑰隨程式碼推上 Git

CLI 與 MCP 沒有瀏覽器登入流程，工程師只好把帳密與 API_KEY 寫死在原始碼與設定檔裡。

Token 發出去就沒人管

誰持有有效 Token、何時過期、能不能撤銷，全都答不出來。出事無法追溯，也沒有即時止血的路。

把機器身分當成一等公民

傳統 SSO 假設使用者面前有一個瀏覽器；AI 時代大量的存取主體，是沒有瀏覽器、非互動式的機器。

以人為中心

傳統 SSO 的前提

  • 使用者打開瀏覽器，輸入帳密登入
  • 每個服務各自接 LDAP 驗證身分
  • 機器帳號用共用密碼或長效 API Key 湊合

機器即一等公民

統一認證閘道 AuthGate

  • 所有服務都是標準 OAuth 2.0 / OIDC Client，新服務從造輪子變成註冊
  • CLI、AI Agent 以 Device Flow + PKCE 登入，沒有任何寫死的金鑰
  • LDAP、Microsoft Entra ID、Gitea 集中於單一入口
  • Token 可查詢、可設到期、可即時撤銷，管理員能強制全體重新登入

45 分鐘怎麼走

每一段的寬度就是它佔的時間。最長的一段，是解法架構本身。

  1. 5 min開場：AI 工具爆發的現場數字
  2. 8 min三大風險：造輪子、金鑰流入 Git、Token 失控
  3. 7 min觀念轉變：機器身分即一等公民
  4. 12 min解法架構：OAuth 2.0 / OIDC 閘道、Device Flow + PKCE、Token 生命週期治理
  5. 8 min落地與踩坑：稽核、限流、監控、群組同步
  6. 5 min收尾與 Q&A

全程以 vendor-neutral 的開源實作與架構決策為主，重點是「為什麼這樣設計」與「踩過哪些坑」。

聽完可以帶走

  • 看懂被 AI 放大的認證風險為什麼 AI Agent、MCP、CLI 的爆發，會讓帳密寫死、Token 失控、認證造輪子變成系統性風險。
  • 一個關鍵的思維轉變以人為中心的 SSO 為何不夠用，以及如何把機器身分納入統一治理。
  • 可立即評估的技術選型Device Flow、PKCE、OAuth 2.0 / OIDC 在無瀏覽器場景的用法，回去就能盤點自家 AI 工具的認證現況。
  • Token 生命週期治理的做法讓 Token 可查詢、可設到期、可即時撤銷，出事時一鍵止血並滿足稽核合規。
  • 一條真實的導入路徑稽核日誌、限流、Prometheus 監控、LDAP / AD 群組同步，以及自建開源與採購商業方案的權衡。
